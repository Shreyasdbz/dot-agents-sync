# Investigation report composition guide

Default to the skill's inline answer. Use this guide when a durable report is requested. Lead with the answer and calibrated confidence, not a chronological transcript of tools.

## Core record

1. **Question and scope:** exact symptom or decision, affected revision/environment/time window, and what was not examined.
2. **Answer:** concise conclusion; label an unresolved hypothesis as such.
3. **Evidence:** observed facts with source/location and timestamp where relevant. Separate observations from interpretations.
4. **Causal account:** explain the chain supported by evidence, competing explanations examined, and what discriminated between them.
5. **Next action and limits:** smallest useful safe action, expected information gain, untested behavior and remaining uncertainty. Diagnosis does not authorize a fix.

Load [variants.md](variants.md) for incident, correctness, performance and research structures. Keep sections proportional; do not require a timeline for a static code question or benchmarks for a qualitative finding. Link raw logs instead of copying secrets or pages of repetitive output.

Use an evidence table only when several claims need traceability: **Claim / Observation / Source / Confidence or gap**. Proposed actions are not completed actions. A pitch deck is a requested projection of the same findings, never stronger evidence.
