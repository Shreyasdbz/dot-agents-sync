# Delegation, challenge and synthesis

## Assign bounded work

For substantive PRs, start with area walkthroughs split by vertical/owning boundary, then targeted independent perspectives across high-risk paths. Use actual host tools/concurrency limits and inspect selected role definitions. Area agents reconstruct mechanisms; challengers assess security/privacy, state/architecture, performance, UX or AI boundaries where relevant. Do not give every agent the entire repo to rediscover or require a reviewer for every label/file/severity. Intentional overlap belongs at shared contracts and disputed mechanisms.

Assign an owner to every changed group and cross-area contract edge. Schedule depth around privileged/durable paths, fan-out, dependencies, migrations and uncertain evidence. Reuse agents for related follow-ups; forbid recursive delegation by default. Isolate tests writing files or sharing resources; read-only briefs do not authorize mutations. If roles/tools are unavailable, do necessary passes inline and report that no independent agent ran.

## Supply an evidence-bearing brief

Include only authorized context needed for the task:

- Outcome/question; exact repository paths, immutable base/head/merge-base/current primary; comparison type and permitted snapshot locations.
- Files/vertical and boundary ownership, verified entrypoints, applicable requirements/guidance and project facts with provenance; named unknowns rather than private-context dumps.
- Actions/tools allowed; read-only default, isolated verification limits, no implementation/publication/live effects, privacy limits and no further delegation unless explicitly authorized.
- Required evidence: success/failure path, candidate location/trigger/impact, invariant owner, base/head causality, strongest counterevidence, commands/results and unexamined boundaries.

Request supported findings, dismissed candidates with decisive counterevidence, gaps and actual checks. No findings with concrete coverage is useful. Independent reviewers form their own hypotheses from code; disclose a candidate when a focused falsification pass is needed. Do not ask agents to manufacture a blocker, rubber-stamp a preferred fix or treat an earlier summary as authority.

## Lead obligations

Map returns to the coverage ledger and inspect consequential evidence at its owner. Agent agreement is not proof. Deduplicate root causes; resolve conflicting path/environment assumptions against code, requirements or focused checks. Follow boundaries end to end when separate area returns leave gaps. Missing/failed agent work stays visible; dispatch targeted follow-up where useful instead of counting it complete.

For each finding establish location in the pinned diff (or narrow unchanged boundary explaining it), reachable trigger, consequence, causal change/requirement gap, counterevidence and feasible minimal correction. Do not anchor to an unrelated changed line to satisfy a provider; use a general comment naming the exact boundary when needed. Reject unsupported suspicions as findings but retain material unresolved gates in verdict limits.

Judge severity by impact/preconditions using skill definitions. Separate optional organization preferences from contract failures. Explain what resolves blockers/unknown required gates and the focused verification. Approve means no supported blocking findings in examined scope; it does not certify unreviewed areas, unrun gates or production operation.

Audit final findings for stale revisions, contradictory evidence, unnecessary refactors, duplicates, unsafe payloads, private data and unsupported performance/completion claims. Return concise verdict/findings/material limits inline; preserve identities/evidence across requested artifacts and authorized posting. Separately record source-inspected, executed local, mocked, external and independent-review evidence. Agent count, elapsed time and static content checks do not establish review quality or behavioral model capability.
