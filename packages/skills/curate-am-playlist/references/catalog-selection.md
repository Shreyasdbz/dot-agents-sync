# Selecting Apple Music catalog tracks

Use this when an Apple Music catalog search, connected tool or public Apple Music page can return candidate tracks. Apply the checks to the listener's storefront; a result in another storefront does not establish local availability. Search both songs and albums when the first hit could be a single, compilation, reissue or clean edition. Inspect enough candidates to resolve plausible variants rather than taking the first search result. Rank candidates by the requested recording and content preference first, then by release provenance among valid versions.

## Resolve the intended recording and release

1. Match artist and title, then the requested studio, live, remix, edit, remaster or featured-artist version. Use duration, ISRC, release metadata and preview or listening evidence when available to distinguish ambiguous recordings. An ISRC can map to several Apple Music song IDs, so it does not by itself choose the release.
2. Prefer the track on the artist's primary full album when it exists in the storefront, especially over a later compilation, republish, sound-alike or isolated single. Favor the original standard album over a deluxe or reissue when both contain the same intended master, unless the listener asks for the later version or it is the only usable one. A song that was intentionally released only as a single is fine; a compilation can be right for a compilation-exclusive track. Do not substitute a different mix just to get an album listing.
3. Verify the candidate's album relationship or album track list where available. Album title text alone does not prove provenance. Use the album's artist, release date, `isCompilation`, `isSingle` and track list as evidence, while allowing legitimate exceptions such as soundtracks and multi-artist albums.

## Resolve the content version and ID

4. Compare the song's own `contentRating` across plausible equivalents. If the intended recording has explicit and clean catalog versions and the listener has not asked for clean, select the explicit song. Search the explicit album edition and alternate results when the first hit is clean. Do not apply an explicit-content restriction when seeking explicit tracks: Apple's `restrict=explicit` can replace them with clean equivalents. A missing rating means unrated, not verified clean or verified explicit. An album-level badge does not establish every track's rating.
5. Confirm the chosen *song* resource ID, its storefront, album, song-level rating and availability or playable status immediately before using it. In an Apple Music album URL, the album path ID is not the song ID; verify the selected track's own ID or `?i=` value. Do not pass an album ID, ISRC, library ID or a different version's ID as the catalog song ID. If a tool exposes only a library song, use its catalog mapping when available and verify the mapped song. If exact identity or a preferred explicit version remains unresolved, say so and offer the best verified alternative; when explicit is preferred, never silently swap in a clean or unrelated recording.
6. Deduplicate the same intended recording across duplicate catalog entries while retaining distinct versions when they serve the playlist. Record the chosen song ID and Apple Music link if verified, plus any consequential substitution. Recheck the created or edited playlist for the actual IDs and order, since a catalog match is not proof that an account write succeeded.

Apple documents [song ratings and ISRC](https://developer.apple.com/documentation/applemusicapi/songs/attributes-data.dictionary), [album metadata](https://developer.apple.com/documentation/applemusicapi/albums/attributes-data.dictionary), [multiple IDs per ISRC](https://developer.apple.com/documentation/applemusicapi/get-multiple-catalog-songs-by-isrc), and [clean substitutions and storefront equivalencies](https://developer.apple.com/documentation/applemusicapi/managing-content-ratings-alternate-versions-and-equivalencies).
