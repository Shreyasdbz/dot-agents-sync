## Implementation choices

Reuse the repository's canonical HTML foundation, with a small quiz behavior module and scoped CSS. Ship a worked, explicitly fictional two-snapshot example and a usage contract as template.change-quiz; require it from skill.change-quiz. No library, external asset, model API wrapper, executable package or storage is needed. The host agent studies the actual source and authors the artifact; the template handles only display and answer interaction.

History uses complete immutable snapshot sections in one native collapsed disclosure. It preserves past explanations when current behavior changes. A source fingerprint supplements HEAD for working bytes. A persistent answer store would add privacy and migration concerns without a requested benefit, so answers last only for the current page session. The HTML cannot update its own local file; the skill updates the authorized artifact on the next run while preserving prior sections and a recoverable original.

Verification separates catalog packaging/materialization, generated-source parity, executed browser interactions, rendered composition and source-grounded question quality. Static tests do not prove runtime model judgment or customer/service behavior. Maintained browser checks exercise selection, retries, history, print restoration, themes, narrow layouts and the no-JavaScript reading fallback. Future forward tests should supply raw changes and evaluate the produced quiz against actual code; do not supply expected questions to the producing agent.
