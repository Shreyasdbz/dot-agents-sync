# Pitch Deck

Make the source easier for its audience to understand or decide. Determine the audience and intended outcome; ask only if a different answer materially changes the story. Read the source before outlining.

Build the shortest coherent narrative. Each slide has one job and a title that conveys its point; titles alone should explain the argument. Put the outcome early, evidence near the claim it supports, and interruptive depth in an appendix. Do not force every subject into the same slide count or sequence.

Apply [Visual Artifacts](references/skill.visual-artifacts/SKILL.md) for composition, diagrams, interaction and motion; load its focused references only when needed. Choose a visual thesis for the deck: the relationship the audience must understand, its strongest evidence, and a coherent type/palette/diagram grammar suited to the source and selected preferences. Preserve denominators, units, dates and caveats on quantitative claims.

Storyboard by slide purpose before building. A mechanism needs a labeled diagram and worked example; a comparison needs aligned criteria; a change needs connected before/after states; a decision needs evidence beside its consequence. Vary composition with the argument instead of repeating title-plus-cards. Give each slide a dominant visual and clear reading order. Use precise labels and visible uncertainty; remove ornamental diagrams, invented metrics and unsupported certainty.

Load [deck.html](references/template.pitch-deck/deck.html) as a working shell and [components.md](references/template.pitch-deck/components.md) to select relevant charts, data flow, entity relationships, synchronized step-through scenes and dense layouts. Adapt or draw a more suitable visual when the relationship differs from the examples. Use direct subject or decision titles. Keep ordinary slides focused; use a dense slide when related contracts, code and evidence must be understood together. Preserve readable type instead of shrinking to a fixed canvas.

Use transitions to connect scenes and synchronized highlights to explain a mechanism. Keep state updates immediate and rapid navigation reliable. Temporal explanations offer manual stepping, opt-in play/pause and replay; no essential fact depends on animation. Keep a complete readable no-JavaScript, reduced-motion and print version. Avoid applying the same entrance effect to every fragment.

Render and critique before completion when a browser is available. Inspect every slide for hierarchy, diagram geometry, label legibility, missing content and sample facts. Test keyboard/pointer navigation, rapid traversal, sequence controls, narrow and presentation-sized viewports, zoom, both supported themes, reduced motion and printing. Revise observed failures; distinguish appearance from executed interaction checks. If rendering is unavailable, label visual verification as outstanding.

Deliver one self-contained HTML file with its CSS/JavaScript and concise verification notes. Load context.artifact-routing for its destination. It must communicate without presenter coaching. External hosting or sharing requires separate authority.
