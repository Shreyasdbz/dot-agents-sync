# Pitch Deck

Make the source easier for its audience to understand or decide. Determine the audience and intended outcome; ask only if a different answer materially changes the story. Read the source before outlining.

Build the shortest coherent narrative. Each slide has one job and a title that conveys its point; titles alone should explain the argument. Put the outcome early, evidence near the claim it supports, and interruptive depth in an appendix. Do not force every subject into the same slide count or sequence.

Choose visuals for relationships—comparison, sequence, causality, scale, ownership or structure. Use concrete examples for technical explanations. Remove repeated points, ornamental diagrams, generic card grids, invented metrics and unsupported certainty. Design follows the source and selected preferences, not a fixed visual trope. Preserve denominators, units, dates and caveats on quantitative claims.

Load [deck.html](references/template.pitch-deck/deck.html) as the presentation shell, not as a finished design. Load [components.md](references/template.pitch-deck/components.md) for charts, data flow, entity relationships, step-through sequences and dense context layouts. Use direct subject or decision titles, not slogans. Keep ordinary slides focused; use a dense slide when understanding depends on seeing related contracts, code, evidence or distinctions together. Organize detail into labeled groups and preserve readable type instead of forcing a word-count ceiling or moving necessary context to an appendix. Retain keyboard navigation, focus, reduced motion and print behavior.

Render before completion when a browser is available. Test keyboard and pointer navigation, narrow and presentation-sized viewports, zoom, overflow and printing. Inspect every slide for missing content and placeholders. If rendering is unavailable, perform structural checks and label visual verification as outstanding; do not claim the deck looks correct.

Deliver one self-contained HTML file with its CSS/JavaScript and concise verification notes. It must communicate without presenter coaching. External hosting or sharing requires separate authority.
