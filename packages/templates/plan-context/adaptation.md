# Plan Context adaptation

The JSON/YAML schema is the machine contract; this guide does not add fields. Use the entrypoint to load the current schema. Never place a tracker key into a portable ID field.

- **Localized bug:** one active milestone, one coherent phase, the smallest verifiable tasks. Do not pad work to meet nominal sizing minima.
- **Feature:** phases deliver usable vertical outcomes. Tasks carry acceptance and verification alongside behavior; optional scope and human_input expose boundaries and blockers.
- **Migration:** phase outcomes describe safe intermediate states. Use dependencies for actual gates and rollback for relevant PR-boundary limits.
- **Greenfield program:** expand only the immediate milestone; each future milestone has exactly one planning_task and no phases.
- **Existing tracker:** preserve known references/status with provenance. Use authority_state for current, snapshot or unavailable evidence. Proposed hierarchy mappings do not establish actual native fields.
- **Offline planning:** portable IDs can coexist with unresolved external references. Produce a valid draft, then refresh and reconcile before authorized publication.

Human projections may use richer headings, tables or diagrams, but they must not become a second writable authority or silently drop machine-context blockers. Load only the immediate work needed for execution.
