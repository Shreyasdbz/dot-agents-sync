# Visual quiz artifact contract

Adapt [quiz.html](quiz.html), a fictional worked example with two current questions and an older snapshot. Copy [components/question.html](components/question.html) for additional questions. Remove sample facts, evidence and authoring comments from the final artifact. CSS and behaviors are inline; the page opens offline with no dependencies or network requests. The authoring source lives in template-system, not this generated distribution file.

## Visual language and interaction

Keep the quiz's minimal technical visual language: spacious hierarchy, smooth nested corners, restrained blue/mint/violet mesh gradients behind the header, neutral reading surfaces and rounded diagram nodes with distinct connectors. The gradient is static; text remains readable without translucency. Reuse the inline quiz palette in light and dark themes instead of importing the shared editorial palette over it. Adapt diagrams to actual relationships rather than adding decorative card grids.

Selections receive an immediate textual result and a calm green or amber selected-choice treatment; color never supplies the answer alone. Retry clears that treatment and returns focus to the first choice. The answered count has a matching visual progress line, independent for each snapshot. Brief press feedback, explanation arrival and history expansion use opacity/transform; no perpetual motion or animation gates. Reduced motion updates immediately, including preference changes during use. Keep empty result space collapsed, preserve native controls, and print every explanation as static text.

## Snapshot structure and updates

Keep one main heading and a current section with data-quiz-snapshot immediately above a single details.disclosure#quiz-history containing all earlier snapshot sections, newest first. Omit history when it is empty. Each snapshot has a globally unique id, a stable data-snapshot-id, its own heading, comparison metadata, scope/unknowns note, question list and data-quiz-progress status. Preserve full base/head identities, PR URL/repository when known, generation date and fingerprint for local changes. Display short hashes only alongside available full identities; fictional sample labels are not valid real revision identifiers.

On a new run, first read and validate the authorized existing artifact's series identity and snapshot metadata. Preserve a recoverable copy outside source control before changing it. Build a new complete section, move the former current section to the top of the existing history body, leave every older section intact, and insert the new section above history. Never recursively nest previous HTML documents or history containers. Use the existing foundation unless a migration is necessary, and verify old data attributes still work with its script. Reuse identical snapshots/coverage rather than making duplicates; label same-revision corrections explicitly. Refuse an unrelated file or unknown custom format instead of destructively rewriting it. Preview and compare before atomic replacement; retain the original until verification succeeds.

Snapshot identity includes repository/series, comparison and content fingerprint; full HEAD alone is insufficient for working changes. Never replace old evidence or answers with references to new source. New revision headings describe what changed since the preceding snapshot. History is collapsed by default; section deep links open it. Old sections still allow answering independently, and their progress never contributes to current progress. Collapsing history is an interface action, not deletion or redaction.

## Question markup

An article[data-quiz-question] has one heading, a meaningful figure with its equivalent scenario text, fieldset/legend, four labeled input[type=radio] elements and a data-quiz-feedback block. Assign unique IDs and a unique radio name per question across all snapshots. Each radio has a stable value and data-correct="true" or "false", exactly one true. Each corresponding explanation has data-explanation matching that value and a visible Correct/Incorrect label. Put source anchors and answer-revealing diagrams inside feedback. A blank data-quiz-result role=status announces selection results; data-quiz-retry clears that question alone. The script shows feedback after any selection without moving focus; further selections update the result.

The behavior validates question shape before enabling it. Invalid questions retain readable static explanations and display an actionable error instead of silently grading. Each data-quiz-progress counts answered valid questions in that snapshot. Do not add an exam score, mastery claim or readiness verdict. Answers are session-only and reset on reload; section content persists in the file.

Use actual entity names and labeled relationships. A sequence, before/after state, schema delta, ownership lane or customer journey should carry the reasoning. A missing step is explicitly unknown in both the visual and equivalent text; full resolution appears only in feedback. Use HTML for responsive sequences; inline SVG for geometry with unique title/description IDs and readable mobile alternatives. Do not render untrusted source HTML, rely on remote Mermaid, or expose answers in question captions/accessibility labels.

## Fallbacks and checks

Feedback is readable in source markup without JavaScript; enhancement hides it until answered. Print includes all questions and feedback, including collapsed history and unanswered questions, then restores disclosure/feedback state afterward. Show a no-JavaScript note explaining that self-grading is unavailable. Retry/theme/print controls are hidden until operational. Use the foundation's focus, theme and print tokens; retain native keyboard radios and disclosures.

Escape source text, validate any links, and never insert untrusted text using innerHTML. No fetch, CDN, analytics, answer storage or private context bodies belong in the file. Check content even in comments, attributes, answer keys and history. Verify selections for all four options, all explanations, retry isolation, per-snapshot progress, keyboard arrows/Space/Tab, history and hash reveal, repeated print restoration, no-JavaScript reading, reduced motion, both themes, 320px and zoom. Rendering is distinct from content grounding; report unperformed checks.
