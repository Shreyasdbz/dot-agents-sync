# Workspace artifact design

Private binding contract; no workspace branding or assets are bundled.

Capture the workspace's HTML artifact audience, brand scope, verified logo and icon sources, offline asset locations, typography, light/dark palette roles, spacing, component treatments and exceptions. Distinguish measured reference values from chosen adaptations; date sources and record access or export limits. Include a compact CSS override and asset embedding recipe when useful, preserving one authoritative private source.

Apply the same brand across reports, proposals, decks, quizzes and other HTML compositions belonging to that workspace while retaining each format's content structure and interactions. Do not brand unrelated work or retroactively edit existing artifacts without authorization. Keep semantic status colors separate from the brand accent. Preserve labels, keyboard focus, readable contrast, reflow, reduced motion, no-JavaScript reading and print.

Walk through every used component and state: header/navigation, typography, panels/disclosures, tables/code, charts/diagrams, controls, errors/empty states and format-specific interactions. Record actual render and interaction evidence at narrow/wide sizes, zoom and both supported themes. Pixel inspection must address alignment, spacing, padding, line length, weight, tracking, icon geometry and clipping; an unrendered token list is not visual verification.

Keep private context bodies, local paths and proprietary assets out of public catalog files and generated authoring comments. Inline only assets needed by the authorized artifact; no remote font, icon or analytics dependency. Missing assets or access remain named gaps rather than invented substitutes. Context does not authorize publication, additional grants or deployment.
